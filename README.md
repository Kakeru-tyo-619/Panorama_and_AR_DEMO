# NPLMAP Panorama デモ版

スマートフォンのブラウザで「その場で一周して自動撮影 → 奥行き付きパノラマ生成 → 立体360度ビュー / AR で閲覧」までが実機で成り立つかを検証するためのデモです。
バックエンドはなく、データはすべて端末の IndexedDB に保存されます。

- React + TypeScript + Vite / three.js
- 奥行き推定：`@huggingface/transformers`（depth-estimation パイプライン、`onnx-community/depth-anything-v2-small`）。WebGPU → 使えなければシングルスレッド WASM
- 合成・奥行き推定は Web Worker（OffscreenCanvas）で実行

## 1. インストールとローカル起動

```bash
npm ci
```

```bash
npm run dev
```

`http://localhost:5173/-Panorama_and_AR_DEMO/?mock=1` を開くと PC 用のモックモードで動きます（localhost は HTTPS でなくてもカメラ・センサー API が使えます）。

### スマホからローカルの開発サーバーを開く（HTTPS）

カメラと方位センサーは HTTPS でしか動かないため、同じ Wi-Fi のスマホから試すときは HTTPS で起動します（`@vitejs/plugin-basic-ssl` の自己署名証明書）。

```bash
npm run dev:https
```

表示される `https://<PCのIP>:5173/-Panorama_and_AR_DEMO/` をスマホで開き、証明書の警告を許可して進みます。
iOS Safari は自己署名証明書だと方位センサーの許可ダイアログが出ないことがあるため、**実機確認は基本的に GitHub Pages の公開URLで行ってください。**

### 本番ビルドの確認

```bash
npm run build
```

```bash
npm run preview
```

## 2. GitHub Pages への公開

`main` ブランチに push すると `.github/workflows/deploy.yml` が `npm ci → npm run build → configure-pages → upload-pages-artifact(dist) → deploy-pages` を実行して公開します（Actions タブから手動実行 `workflow_dispatch` も可能）。

初回だけ次の設定が必要です。

1. GitHub でリポジトリを作成し、このフォルダを push する
2. リポジトリの **Settings → Pages** を開く
3. **Build and deployment → Source** を **「GitHub Actions」** にする
4. `main` に push（または Actions タブで「Deploy to GitHub Pages」を Run workflow）
5. 完了すると公開URL **https://kakeru-tyo-619.github.io/-Panorama_and_AR_DEMO/** で公開される

`vite.config.ts` の `base` は、ワークフローが `VITE_BASE=/${{ github.event.repository.name }}/` を渡すので、**リポジトリ名に自動で合わせられます**（ローカルでの既定値も `/-Panorama_and_AR_DEMO/`）。
Worker・WASM などのファイルは Vite が `base` を前提に解決します。画面遷移は URL のパスを使わない（状態で切り替える）ので、下層パスの 404 は起きません。

## 3. スマホでの試し方

1. 公開URL https://kakeru-tyo-619.github.io/-Panorama_and_AR_DEMO/ を iPhone（Safari 16.4 以上推奨）または Android（Chrome）で開く
2. 「撮影する」→「撮影開始」。カメラと方位センサー（iOS）の許可を求められるので許可する
3. スマホを縦に持ち、その場でゆっくり一周する。上部の方位バーで撮影済みの区画が緑になり、矢印が次に向く方向を示す
   - 水平線が赤いときは前後に傾きすぎ（±10°）。速すぎる・傾きすぎると注意が出て、やり直し回数が増える
   - 12区画撮ると自動で終了。6区画（180°）以上で「ここで終了」も押せる
4. 生成画面でパノラマ合成 → 奥行き推定（初回はモデルを数十MBダウンロード。2回目以降はブラウザのキャッシュを使用）
5. 閲覧画面
   - **立体360度**：ドラッグ／ジャイロを切り替え。スマホを左右に傾けると視点が平行移動し、手前と奥がずれて見える
   - **AR**：「AR を開始」でカメラ映像の上に、今向いている方位のパノラマの遠景だけを重ねる。不透明度・奥行きしきい値・左右の微調整・ワイプ比較が使える
6. 右下の **DBG** でデバッグパネル（センサー値、処理時間、FPS、WebGPU、hFOV の変更と「再生成」、奥行きの強さなど）

## 4. モックモード（PC での確認）

URL に `?mock=1` を付けると有効になります（ホーム画面下部のリンクからも切り替え可）。

- **センサーのモック**：左上の「モックセンサー」パネルのスライダー、またはキー操作（←→ 方位 / ↑↓ 前後 / Q E 左右、Shift で大きく）。「自動で回す」で一周撮影を再現できる
- **合成カメラ**：手続き的に作った360°の風景（山・建物・木・方位ラベル、横画角 65°）を、モックの方位・傾きで透視投影して表示する。向きによって明るさを変えて、自動露出の差も再現している
- **撮影のモック**：撮影画面の「画像ファイルから撮影済みにする」で複数の画像を選ぶと、選んだ順に方位（開始方位＋間隔、既定 0°・30°ごと）を割り当てて生成に進む
- AR もモックでは合成カメラを背景にするので、撮った直後のパノラマとの重なり具合を PC で確認できる

## 5. 検証スクリプト

```bash
npm run test:stitch
```

合成画像（既知の方位・pitch・roll・露出差）を作って合成し、真の模様との誤差と、明るさ合わせの係数を表示します。
実測：pitch ±9°・roll ±8°・露出差 ±18% の12枚で、平均誤差 0.59/255、係数は露出の逆数と一致（全体の正規化分を除く）。

```bash
npm run test:pose
```

既知のカメラ姿勢から W3C の Euler 角（alpha/beta/gamma）を作り、方位・pitch・roll に戻せるかを確認します（誤差 0.0000°）。

## 6. 実装メモ（仕様の解釈）

| 項目 | 実装 |
| --- | --- |
| 方位・傾き | iOS は `webkitCompassHeading`、Android は `deviceorientationabsolute`。pitch/roll は beta/gamma から回転行列を組んで「背面カメラの向き」と「端末の右・上」を求めて計算する。縦持ち（beta≈90°）では Euler 角が特異になり gamma をそのままロールに使えないため。gamma≈0 のとき方位は仕様どおり `360 − alpha` と一致する |
| 平滑化 | 直近5サンプルの移動平均。角度は sin/cos のベクトル平均 |
| 回転速度 | 約100ms前の値との角度差 ÷ 時間（イベント間隔のばらつきに強くするため） |
| 傾き補正・円筒投影・配置 | パノラマの各画素から「どの写真のどの画素か」を逆算する1回の写像で行う（roll の逆回転・pitch の上下補正・atan による円筒変換と同じ結果で、補間が1回で済む）。0°/360°をまたぐ画像は両端に描く |
| 明るさ合わせ | 1/4 解像度で隣同士の重なり部分の平均輝度を求め、log 係数の最小二乗で全体の係数を決定。全体の平均輝度が変わらないよう正規化 |
| 境目のぼかし | 画像の左右の端に近いほど小さくなる線形の重みで加重平均 |
| パノラマサイズ | 横 4096px、縦はカメラの縦画角から（hFOV 65°・縦持ちで約 1478px）。上限 2048px（iOS の Canvas 面積制限に余裕を持たせる） |
| 奥行き推定 | 2048px 幅に縮小したパノラマを 8 タイル（両端20%重ね）に分けて推定。各タイルを 2%/98% 分位点で正規化し、重なりを線形に混ぜる。出力 1024px 幅の PNG（近いほど白） |
| モデル | WebGPU：`shader-f16` が使えれば fp16（約50MB）、なければ fp32。数値が壊れたら fp32 で読み直す。WASM：q8（約27MB）・1スレッド |
| 立体360度 | 512×128 分割の円筒。半径 = 基準半径 ×（1 − 強さ × 奥行き値）。視点は腕の長さ相当だけ前方＋傾き／ドラッグに応じて左右・上下に平行移動。上下端は空・地面色のグラデーションへフェード |
| AR | パノラマを変形なしの円筒に貼り、背景映像（object-fit: cover）と同じ画角の three.js カメラを方位・pitch・roll で回す。奥行きしきい値より遠い部分だけを表示（境目は smoothstep） |

### 仕様から補った点（要確認）

- **`coverage_mask`（Panorama に追加）**：仕様では `panoramaBlob` が JPEG で、かつ「未撮影部分は透明」とあり、JPEG では透明を保存できません。そのため JPEG のまま保存し、未撮影の範囲は 1°ごとのフラグ（360文字の '0'/'1'）として持たせました。
  代替案：① PNG で保存（容量が数倍） ② WebP（透明あり。ただし Safari は Canvas からの WebP 書き出しに未対応） ③ 本番では撮影範囲を `coverage_deg` と開始方位の組で表す
- **`raw_shots`（IndexedDB のストアを追加）**：デバッグパネルの「hFOV を変えて再生成」のため、元写真を panorama_id ごとに保存しています（1件あたり数MB）。本番では不要です
- **相対方位しか取れない端末**：仕様では「方位が取れない端末は撮影不可」ですが、`deviceorientation` の相対値だけ取れる場合は警告を出したうえで撮影できるようにしています（一周の中では方位がそろうため合成は可能。AR の位置合わせはずれる）。不要なら `src/lib/sensors.ts` の `relative` を無効にしてください

## 7. 既知の問題と、本番に向けて検討が必要な点

### 処理時間（実測）

| 環境 | 合成 | 奥行き推定 | 備考 |
| --- | --- | --- | --- |
| Windows PC / Chromium（モック、12枚 360×640） | 2,152 ms（Worker） | 32,346 ms | WebGPU fp16。初回のモデルダウンロード込み |
| Node.js（`npm run test:stitch`、合成のみ） | 1,474 ms | — | |
| iPhone / Android 実機 | 未計測 | 未計測 | 情報画面・デバッグパネルに表示されるので、実機で記録してください |

実機では写真が 1080×1920 程度になり、合成は PC の数倍、WASM での奥行き推定は 1タイル数秒〜十数秒かかる見込みです。

### 既知の問題・制約

- **iOS 16.0〜16.3**：OffscreenCanvas がないため、合成はメインスレッドで実行（画面が数秒固まる）。transformers.js の画像前処理も OffscreenCanvas を使うため、奥行き推定は失敗し「奥行きなし」で保存されます（16.4 以上で動作）。回避するならパイプラインを使わず、前処理（リサイズ・正規化）を自前で行って `AutoModel` を直接呼ぶ方法があります
- **iOS の方位**：`webkitCompassHeading` は縦持ちでも背面カメラの方位を返す前提です。端末を大きく傾けると値が跳ぶことがあり、磁北基準（真北ではない）です
- **画面の向き**：縦持ち（portrait）前提です。横向きにすると方位・傾きの計算がずれます（`screen.orientation.angle` による補正は未実装）
- **hFOV**：端末から取得できないため既定 65°。縦持ちの映像の「横」の画角としては広めの端末が多いので、合成の継ぎ目がずれる場合はデバッグパネルで変えて再生成してください（モックの合成カメラは 65°）
- **視差・奥行き**：単眼推定の相対深度を円筒の半径に写しているため、前景と背景の境目でメッシュが引き伸ばされます（ゴム膜状）。奥行きの強さを上げすぎると目立ちます
- **奥行きの尺度**：タイルごとに正規化しているため、タイルの境目で遠近の尺度が少し変わることがあります
- **特徴点による位置合わせはしていない**：センサーの誤差（数度）がそのまま継ぎ目のずれになります。本番では方位で初期配置 → 重なり部分のテンプレートマッチング等で微調整が有効
- **撮影中の手の位置**：その場で回るとカメラが回転中心から 30〜40cm 離れるため、近い物体には視差による二重像が出ます
- **ORT の WASM（約27MB）**：transformers.js が参照する ONNX Runtime の WASM が `dist` に含まれます（モデル本体は含めず、実行時に Hugging Face から取得）
- **ローカル開発サーバーの注意**：Windows でプロジェクトが仮想化されたフォルダ（Microsoft Store 版アプリの AppData 配下など）にあると、Vite の開発サーバーが Worker を `/@fs/` の実パスで読もうとして失敗することがあります。その場合は `npm run build && npm run preview` で確認してください（本番ビルドには影響しません）
- **AR の位置合わせ**：方位センサーの誤差でずれる前提で、左右の微調整スライダーを付けています。`heading_correction` はデモでは常に null

### 本番に向けて

- 季節間の向きの自動補正（`heading_correction`）：パノラマ同士の遠景（スカイライン）の相互相関で求める方法が有力
- 人物検出・ぼかしは主サービスの機能と連携
- 保存形式（JPEG＋撮影範囲 / PNG / WebP）とサイズ（4096px で約 1〜2MB）の決定
- 奥行きマップの解像度と保存形式（16bit PNG にするか）
- 撮影範囲が 360° 未満のときの閲覧時の扱い
