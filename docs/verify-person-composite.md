# 人物合成モード 検証デモ（iPhone）

パノラマの 3D 表示・カメラ映像の取り込み・人物の切り抜き・合成を**同時に動かして、iPhone の Safari で落ちないか**を確かめる技術検証用のページです。
詳しい方針は [人物合成モード 実装方針](person_composite_mode.md) を参照。

- 検証ページ：公開サイトの URL の末尾に `?mode=verify` を付ける（例：`https://<ユーザー名>.github.io/<リポジトリ名>/?mode=verify`）
- 生成処理（撮影・合成・人物検出・奥行き推定）は検証ページでは一切動かさない。保存済みのパノラマ画像と奥行きマップを読み込むだけ
- **撮影データはリポジトリにも公開サイトにも置かない**（GitHub Pages は誰でも見られるため）。端末から端末へファイルで渡す

## 1. PC でデータを作って保存する

1. PC のブラウザで、本編のデモ版を開き、いつもどおりパノラマを撮影・生成する（仕上がり確認画面まで進む）
2. 仕上がり確認画面の「**検証用に保存**」を押す。次の 3 ファイルが保存される（ファイル名に生成日時が入る）
   - `pano_YYYYMMDD-HHMM.jpg`：パノラマ画像（生成したままの解像度・画質。再圧縮しない）
   - `depth_YYYYMMDD-HHMM.png`：奥行きマップ（8 ビット白黒 PNG。**白＝近い、黒＝遠い**。メートルではなくタイルごとに正規化した相対値）
   - `info_YYYYMMDD-HHMM.json`：画像の縦横、奥行きの形式・値の範囲・向き、`heading_start`、`coverage_deg`、`coverage_mask` など
3. PC ではダウンロードされる（Chrome は複数ダウンロードの許可を聞くので許可する）。スマホでは共有シートが開く

## 2. iPhone にファイルを送って読み込む

1. PC から iPhone へ 3 ファイルを送る（AirDrop、または iCloud Drive の共有フォルダに入れる）
2. iPhone の「ファイル」アプリで、受け取った場所（「AirDrop」の保存先＝ダウンロード、または iCloud Drive）に 3 ファイルがあることを確認する
3. Safari で検証ページ（`?mode=verify`）を開き、「ファイルを選択」→「ブラウズ」で、3 ファイルを**まとめて**選ぶ
4. 「データ」欄にパノラマの大きさ・奥行き・方位が表示されれば成功。データは端末内（検証ページ専用の IndexedDB）に保存されるので、ページが読み直されても選び直し不要
5. 「データを消す」で削除できる（本編の保存領域とは別）

## 3. 動かし方

画面の「段階」のリンクで段階を選び、「開始」を押す。**段階を変えるたびにページを読み直す**（メモリをまっさらにして比べるため）。
開始ボタンの操作の中で、方位センサーとカメラの許可を求める（iOS は必須）。

| 段階 | 内容 |
| --- | --- |
| 0 | パノラマの 3D 表示のみ（高解像度のまま）。端末の向きで見回す |
| 1 | ＋カメラ映像。仮マスク（画面中央の楕円）の部分だけカメラ映像を見せる |
| 2 | ＋人物の切り抜き（MediaPipe ImageSegmenter、GPU、VIDEO モード）。人物は常にパノラマの手前 |

段階 3（足元からの距離推定と影）は、段階 2 が実機で合格してから着手するため未実装。

### URL パラメーター

| パラメーター | 既定値 | 意味 |
| --- | --- | --- |
| `mode=verify` | — | 検証ページにする（必須） |
| `stage` | `0` | `0` / `1` / `2` |
| `msaa` | `0` | `1` でアンチエイリアス（MSAA）オン |
| `dpr` | iPhone は `1.5`、他は `2`（最大でも `devicePixelRatio`） | 描画解像度の倍率 |
| `mipmap` | `0` | `1` でパノラマのミップマップを作る |
| `mesh` | `256x64` | 奥行きメッシュの分割数（例：`512x128`） |
| `depth` | `1` | `0` で奥行きによる立体表示をやめて平面表示 |
| `ds` | `0.6` | 奥行きの強さ（0〜0.95） |
| `cam` | `back` | `front` で前面カメラ（左右反転して表示）。画面のボタンでも切り替え可 |
| `model` | `selfie` | 切り抜きモデル。`selfie`＝selfie_segmenter（軽い・自撮り向け）、`deeplab`＝deeplab_v3（汎用・離れた人向け） |
| `delegate` | `gpu` | `cpu` で CPU 実行（GPU が作れないときは自動で CPU に落ち、HUD に実際の方を表示） |
| `hz` | `20` | 切り抜きの目標回数/秒（1〜60） |
| `mix` | `0.4` | 前回のマスクを混ぜる割合（0〜0.95。大きいほどなめらかだが遅れる） |
| `inv` | `0` | `1` でマスクを反転（selfie でマスクが逆に出た場合の保険） |

例：`?mode=verify&stage=2&model=deeplab&hz=15&dpr=1.25`

### デバッグ表示

画面左上の半透明パネルに、段階・有効な設定、描画/切り抜き/カメラの回数/秒、切り抜き 1 回の処理時間（ms）、経過時間、`renderer.info.memory`、テクスチャの大きさと GPU メモリの概算（幅×高さ×4 バイト、ミップマップありは×1.33）を出す。
下のボタン：HUD 隠す／**JSON コピー**（結果を貼り付けて記録できる）／ジャイロ⇔ドラッグ／前面⇔背面／終了。

### 落ちたことの記録

3 秒ごとに、段階・設定・経過時間・最後の計測値を `localStorage` に書く。「終了」ボタンか `pagehide` で正常終了の印を付ける。
次にページを開いたとき、印がなければ最初の画面に「前回は段階 ○・○ 秒で読み直されました」と出る（最近 10 件は履歴にも残る）。Mac の Web インスペクタがなくても、落ちた段階と時間が分かる。

> 注意：`pagehide` は、Safari で別のアプリやタブに切り替えたときにも発生する。切り替えた直後のものは「正常終了」と記録される。落ちるかを見るときは、画面を点けたまま 5 分動かすこと。

## 4. iPhone での確認手順

1. 上の手順でデータを読み込む
2. 次の順に、**各 5 分間**動かして、落ちない・読み直されないことを確かめる（落ちたら記録を表に書き、原因を絞るため設定を 1 つずつ変える）
   1. `stage=0`（既定の軽量化）
   2. `stage=1`
   3. `stage=2&model=selfie`
   4. `stage=2&model=deeplab`
3. 合格の目安：5 分間落ちない／描画 30 回/秒以上・切り抜き 15 回/秒以上（段階 2）／人物の境目が気にならない
4. 落ちたとき：同じ段階で `dpr=1`、`mesh=128x32`、`depth=0`、`hz=10`、`delegate=cpu` を 1 つずつ試す
5. HUD の「JSON コピー」で計測値をコピーして、下の表に書く

## 6. 実装メモ（制約・懸念点）

- **モデルは外部から取得する**：MediaPipe のモデル（`.tflite`）は Google のストレージから読み込む（本編の人物検出と同じ）。初回はネットワークが必要。WASM は同梱
- **`crossOriginIsolated` は使わない**：GitHub Pages ではヘッダーを設定できないため、マルチスレッド（`SharedArrayBuffer`）に頼らない構成
- **selfie モデルのマスクの枚数・向きは実機で要確認**：枚数に応じて使うマスクを選んでいる（1 枚＝そのまま、2 枚＝2 枚目）。HUD の「mask … x○枚」で確認できる。逆に出たら `inv=1`
- **段階ごとに読み直す設計**：段階の切り替えはページの読み直し。終了・エラー時も資源（`ImageSegmenter`、カメラのトラック、テクスチャ、WebGL コンテキスト）を解放する。開始に失敗したときは、確実に手放すため 4 秒後にページを読み直す
- **メモリが大きい箇所**：パノラマのテクスチャ（4096×1024 級で約 16〜20MB、ミップマップで約 1.33 倍）。MediaPipe の GPU delegate は別に WebGL コンテキストを持つため、描画用と合わせて 2 つ分の GPU メモリを使う
- **PC での確認**：合成データで段階 0〜2 の描画・カメラ・マスクの流れ（描画 59 回/秒・切り抜き 15 回/秒の動作）を確かめた。実機（iPhone Safari）の結果は未確認。「検証用に保存」ボタンは型検査とビルドのみ通っており、実際の撮影データでの保存・読み込みは未確認
