# パノラマ・AR 作成仕様（抜粋）

出典：[Irisona_AR&Panorama_plan.md](Irisona_AR&Panorama_plan.md)（T06システム設計書（AR））

本書は、上記設計書のうち **パノラマの撮影・生成・投稿** と **360度ビュー／AR表示** の作成に関わる仕様だけを抜き出したものである。設計書の 5〜14 章（API・画面・認証・入力チェック等）は汎用テンプレートのままでパノラマ/AR固有の記述がないため、対象外とした。「未定」「要検討」「要確認」「仮」と書かれた項目は、元の設計書でもまだ決まっていない。

---

## 1. 概要

主サービス（Irisona）で見つけた場所について、利用者がスマートフォンで撮影・投稿したパノラマ風景を季節ごとに閲覧し、周囲を見渡しながら訪問前のイメージを広げる。AR でカメラ映像にその風景を重ね、その場所にいるような体験もできる。

- 閲覧はログイン不要。撮影・投稿はログインが必要
- 対応端末：iOS Safari 16以上、Android Chrome。PCは閲覧のみ

## 2. 対象機能

| 区分 | 機能 |
|---|---|
| 撮影 | パノラマ撮影（撮影案内／自動撮影）、カメラ映像の取得、方位・傾きの取得 |
| 生成 | パノラマ生成（傾き補正／境目のぼかし／明るさ補正） |
| 奥行き | 奥行き推定（投稿時に1回） |
| プライバシー | 人物検出（主サービスの機能を利用）、人物へのぼかし |
| 投稿 | 仕上がりを確認して投稿、画像アップロード、撮影記録の送信 |
| 表示 | 立体的な360度ビュー、AR表示、表示モード（360度ビュー／AR）の切り替え |
| 補正 | 向きの自動補正（方式・実行場所は未定） |
| 閲覧（関連） | 季節・月の切り替え、時間帯での分類、近くのパノラマのまとめ表示 |

## 3. 処理の流れ

```
撮影（カメラ映像＋方位/傾き、撮影案内・自動撮影）
  ↓
パノラマ生成（端末上：傾き補正 / 境目のぼかし / 明るさ補正）
  ↓
人物検出 → ぼかし
  ↓
奥行き推定（端末上で1回。WebGPU → WASM → 失敗時は奥行きなし）
  ↓
仕上がり確認 → 投稿
  ├─ Cloudinary へ署名付きアップロード（パノラマ画像 / 奥行きマップ）
  └─ API へ画像URL＋撮影情報を送信 → D1（shots / panoramas / capture_logs）
  ↓
閲覧：立体的な360度ビュー ⇄ AR表示
```

## 4. 使用技術

| 項目 | 技術・方針 |
|---|---|
| フロントエンド | React / TypeScript / Vite / Tailwind CSS（Cloudflare Pages） |
| バックエンド | Hono / Cloudflare Workers |
| DB | Cloudflare D1（SQLite） |
| カメラ映像 | `MediaDevices.getUserMedia` |
| 方位・傾き | DeviceOrientation API（iOS：`webkitCompassHeading`、Android：`deviceorientationabsolute`） |
| 位置情報 | Geolocation API |
| パノラマ生成 | 端末上で処理。実装手段（Canvas / Web Worker / OffscreenCanvas など）は保留 |
| 奥行き推定 | Depth Anything V2 Small などを transformers.js で端末上実行（WebGPU / WASM）。iOS Safari の対応状況は要確認 |
| 人物検出 | 主サービスの機能（MediaPipe Tasks Vision ObjectDetector / EfficientDet Lite0）を利用。新たに実装しない |
| 360度ビュー | three.js。奥行きマップでパノラマの面を変形して表示。Photo Sphere Viewer を使うかは要検討 |
| AR表示 | カメラ映像の上に、方位を合わせて別の景色を重ねる（センサーのみによる簡易AR） |
| 画像保存・配信 | Cloudinary。パノラマ画像と奥行きマップを保存。AR利用時は高解像度、それ以外は低解像度で配信。奥行きマップは解像度・縦横サイズ・座標系などをパノラマに合わせる |
| 地図 | MapTiler SDK / MapTiler Cloud |

### フォールバック

- WebGPU がない端末では WASM で処理する。処理できない場合は平面表示にする
- 奥行きマップを推定できなかった場合は `depth_map_url` を空にし、立体表示せず平面で表示する

## 5. 作成時に保存するデータ（仮案）

設計書では DB 設計全体が仮案。パノラマは主サービスの投稿（`shots`）の1件として登録し、パノラマ固有の情報を `panoramas` に1対1で持たせる。

### shots（主サービスへの追加分）

| カラム | 型 | NULL | 制約 | 説明 |
|---|---|---|---|---|
| kind | TEXT | 不可 | CHECK(photo / panorama) | 投稿の種別。既定値 `'photo'`。パノラマは `'panorama'` |

画像URL・緯度・経度・投稿日時などは既存の `shots` の列を使う。

### panoramas

| カラム | 型 | NULL | 制約 | 説明 |
|---|---|---|---|---|
| shot_id | TEXT | 不可 | PK, FK → shots.id | `shots.kind = 'panorama'` の投稿にのみ対応 |
| captured_at | DATETIME | 不可 | — | 撮影日時（端末時刻、JSTで保存）。季節・時間帯はここから求め、別途保存しない（仮） |
| heading_start | REAL | 不可 | — | パノラマ左端の方位（北＝0°、時計回り） |
| coverage_deg | REAL | 不可 | CHECK(180〜360) | 撮影できた水平範囲。360なら「完全版」。水平方向のみを扱う |
| heading_correction | REAL | 可 | — | 向きの自動補正値（度）。補正方式とあわせて未定。パノラマ/ARの表示切り替え時に使う |
| depth_map_url | TEXT | 可 | — | 奥行きマップの画像URL（圧縮後に保存するためURLで持つ）。推定失敗時は空 |

### capture_logs（試作の分析・評価用）

| カラム | 型 | NULL | 制約 | 説明 |
|---|---|---|---|---|
| id | TEXT | 不可 | PK | 記録ID |
| shot_id | TEXT | 不可 | UNIQUE, FK → panoramas.shot_id | 対象のパノラマ |
| device_info | TEXT | 可 | — | 端末の機種・OS |
| shot_count | INTEGER | 不可 | — | 撮影した枚数 |
| duration_ms | INTEGER | 不可 | — | 撮影開始から完了までの所要時間（ミリ秒） |
| retry_count | INTEGER | 不可 | — | 撮り直し回数。既定値 0 |
| created_at | DATETIME | 可 | — | 記録日時。既定値 CURRENT_TIMESTAMP |

## 6. バックエンドの役割（パノラマ/AR関連）

- 画像アップロード署名の発行（Cloudinary）
- パノラマの登録・取得
- 季節ごと・月ごとの取得
- まとめ表示の候補の取得（距離／建造物のタグ）
- 向きの自動補正（方式・実行場所は未定）

## 7. 閲覧時のまとめ表示（関連仕様）

- パノラマは投稿ごとに別IDを持ち、地点IDは持たない（GPS誤差のため、まとめは保存時ではなく閲覧時に行う）
- 地図上のピンは主サービスの処理（縮尺に応じたまとめ）に従う
- まとめ表示の候補：
  - 開いているパノラマから半径○m以内のパノラマ（距離は未定。ピンのまとめ距離より広めでもよい）
  - 主サービスの建造物タグ（`shots.tags`）が同じパノラマ
- 候補にはサムネイル・距離・撮影した季節（月）を示し、同じ場所かを閲覧者が判断できるようにする。まとめは保存せず閲覧中のみ有効
- まとめたパノラマどうしの向きをそろえる必要があるかは要検討

## 8. 制約事項

- パノラマ/ARの投稿は1日1件。JST午前0時にリセットする。写真投稿とは別にカウントする
- DBへの登録は、1日1件の制約を守るためトランザクションを含めて検討する

## 9. 未決・要確認事項（パノラマ/AR関連）

| 項目 | 内容 |
|---|---|
| パノラマ生成の実装手段 | Canvas / Web Worker / OffscreenCanvas など保留 |
| 奥行き推定の iOS Safari 対応 | 要確認 |
| 360度ビューのライブラリ | Photo Sphere Viewer を使うか要検討 |
| 向きの自動補正 | 方式・実行場所・`heading_correction` の扱いが未定 |
| まとめ表示の距離 | 半径○m が未定 |
| まとめたパノラマの向き合わせ | 要否を検討 |
| 季節・時間帯の保存 | 撮影日時から求め保存しない（仮） |
| 主サービスとの関係 | 同じアプリか別アプリか未定（構成は同じ基盤を使う場合の仮案） |
