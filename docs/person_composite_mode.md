# 人物合成モード 実装方針

作成日：2026-10-15
関連資料：[パノラマ・AR 作成仕様（抜粋）](Panorama_AR_spec.md)、[性能の安定化と AR の見せ方：調査まとめ](performance_and_ar_research.md)、[AR を強化できる技術の一覧（工程別）](ar_enhancement_catalog.md)

---

## 0. 要点

- カメラに写っている**人物・物体だけをリアルタイムで切り抜き**、それ以外の視界を**保存済みのパノラマの 3D 空間**に置き換える。
- 風景の奥行きは投稿時に作成済みのもの（`depth_map_url`）を使う。**毎フレームの奥行き推定は行わない。**
- 人物の奥行きは、**切り抜きの足元の位置と身長から距離を 1 つ求める**方式で作る。計算はほぼかからない。
- 現実の背景が見えなくなるので、**コンパスの絶対方位の合わせ込み（E 群）と位置の追跡（F 群）が不要**になる。今の AR の「ずれて見える」問題を構造的に避けられる。

## 1. 背景と目的

### 今の AR の課題

今の AR は「現実のカメラ映像」と「過去のパノラマ」を重ねている。位置合わせが必要な 2 つの世界を重ねているため、次の問題が起きている。

- コンパスの誤差（±10° 前後）による、ずれと揺れ
- iPhone の Safari では WebXR が使えず、景色に貼り付かない
- カメラ映像とパノラマの色・光の違いによる「浮いた」感じ

### 新しい方式の考え方

視界を丸ごとパノラマに置き換えると、比べる相手（現実の背景）がなくなるので、ずれが目立たない。360度ビューの安定感をそのまま使い、カメラからは**人物だけ**を持ち込む。

### 体験

- 「過去の季節・時間の風景の中に、今の自分や友人がいる」体験
- 前面カメラなら自撮り、背面カメラなら友人を写す
- 現地にいなくても楽しめる

## 2. 処理の全体像

### 投稿時（既存。変更なし）

```
撮影 → 合成 → 人物の除去 → 奥行き推定 → Cloudinary（パノラマ・奥行きマップ）＋ D1
```

### 閲覧時（毎フレーム）

```
[センサー] ジャイロ・加速度・コンパス → 向き（D1 の融合フィルタ）
[カメラ]   映像のコマ（C1 でコマに合わせる）
              ├→ 人物の切り抜き（15〜30 回/秒、縮小映像で）
              │     → 境目の補正・時間方向のなめらか化
              │     → 人物の距離の推定（足元方式・身長方式）
              └→ WebGL にテクスチャとして渡す（C2）
[WebGL]    パノラマの 3D 空間（保存済みの奥行きで描画）
              ＋ 人物（カメラ映像をマスクで切り抜き、推定距離に配置）
              ＋ 足元の影・色合わせ
              → 画面
```

### 1 フレームあたりの処理の比較

| 処理 | 今の AR | 人物合成モード |
| --- | --- | --- |
| 風景の奥行き | 保存済み（計算なし） | 保存済み（計算なし） |
| パノラマの描画 | あり | あり（同じ） |
| 方位の照合（E1 など） | 正確に合わせるには必要 | **不要** |
| 人物の切り抜き | なし | **毎フレーム必要**（一番重い部分） |
| 人物の奥行き | なし | 切り抜き＋身長・足元から距離を 1 つ算出（ほぼ計算なし） |

## 3. 各処理の詳細

### 3-1. カメラ入力

| 項目 | 方針 |
| --- | --- |
| 取得 | `getUserMedia`。前面・背面を切り替え可能にする |
| 解像度 | 720p 程度（`1280×720`）。描画用と切り抜き用で共用 |
| WebGL への取り込み（C2） | three.js の `VideoTexture`。`<video>` は非表示にし、`playsinline`・`muted` を付けて再生状態を保つ |
| タイミング（C1） | `requestVideoFrameCallback` で、カメラのコマが更新されたときに人物のテクスチャを更新する |
| 表示の切り取り | 画面いっぱいに映すための縦横比の調整（cover）を、シェーダー側の UV 計算で行う |
| 前面カメラ | 左右反転して表示する |

### 3-2. 向き（パノラマを見回す）

| 項目 | 方針 |
| --- | --- |
| センサーの融合（D1） | ジャイロ・加速度・コンパスを Madgwick / Mahony フィルタで融合（npm `ahrs`）。揺れを抑える |
| 画面の回転（D4） | `screen.orientation.angle` で補正 |
| 絶対方位 | 必須ではない。「実際に向いている方向＝パノラマの同じ方向」にしたい場合だけ、`heading_start` とコンパスで初期の向きを決める |

### 3-3. 人物の切り抜き

| 項目 | 方針 |
| --- | --- |
| モデル | MediaPipe Tasks Vision の Image Segmenter（人物用の軽量モデル）。GPU を使う |
| 実行頻度 | 描画（60 回/秒）とは分け、15〜30 回/秒。間のフレームは前回のマスクを使う |
| 入力サイズ | 縮小した映像（256px 程度） |
| 境目の補正（G4） | 縮小マスクを、カメラ映像の輪郭に合わせて拡大（ガイデッドフィルタ）。シェーダーで処理 |
| ちらつき対策（G5） | 前のフレームのマスクと混ぜる |
| 実行場所 | まずメインスレッド。カクつく場合は Worker に移す（C4。Safari 18〜は MediaStreamTrackProcessor、それ以前は `createImageBitmap` で受け渡し） |

### 3-4. 人物の奥行き（距離の推定）

人物を「推定した距離に立てた板」としてパノラマの 3D 空間に置く。距離は次の 2 つの方式で求める。

**準備：画面上の位置を角度に変える**

```
f_y   = (画面の高さ / 2) / tan(縦の画角 / 2)
θ(y)  = atan((y − 画面中央の y) / f_y) + 端末の下向きの傾き
        （θ は水平線から下向きを正とする角度）
```

- 縦の画角は、カタログの A5 で推定した値を使う。まだない場合は機種ごとの仮の値を使う。
- 傾きは 3-2 のセンサーの値を使う。

**方式 1：足元方式（優先）**

地面に立っている前提で、足元が水平線よりどれだけ下に見えるかから求める。

```
距離 = カメラの高さ / tan(θ_足元)
```

- カメラの高さは、手持ちの高さとして約 1.4m を仮定（設定で変えられるようにする）。
- θ_足元 は、切り抜きの一番下の位置から求める。
- 身長が分からなくても使える。子どもや座った人にも強い。

**方式 2：身長方式（足元が見えないとき）**

```
距離 = 身長 / (tan(θ_足元) − tan(θ_頭))
```

- 身長は約 1.6m を仮定。
- θ_頭 は切り抜きの一番上、θ_足元 は一番下から求める。
- 頭や足が画面からはみ出している場合は使えない。

**使い分け**

| 状態 | 使う方式 |
| --- | --- |
| 足元が画面内にある | 足元方式 |
| 足元が画面外、頭と足の両方は見えない | 直前の値を保つ |
| 足元が画面外だが全身に近い | 身長方式 |

**なめらか化**

フレームごとのぶれを抑えるため、前のフレームの距離と混ぜる（例：`距離 = 0.8 × 前回 + 0.2 × 今回`）。急に大きく変わった値は捨てる。

**立体感の追加（必要になったら）**

1. 体のふくらみ：切り抜きの縁から中心に向かって少しずつ手前に出す。マスクから計算するだけで、ほぼ負荷なし。
2. 骨格の推定（MediaPipe Pose）：手や足ごとに奥行きを変える。モデルが増えるので、負荷とメモリを確認してから。

### 3-5. 合成（シェーダー）

| 項目 | 方針 |
| --- | --- |
| 前後関係 | 試作では「人物は常にパノラマの手前」として重ねる |
| 手前の物による隠れ（後の段階） | 人物の推定距離とパノラマの奥行きマップを画素ごとに比べ、パノラマの方が近い部分だけ人物の手前に描く（※ 4 章の未決事項を参照） |
| 色合わせ（H1） | 人物の部分の色の平均とばらつきを、パノラマの周辺の色に寄せる。強さは調整できるようにする |
| 足元の影 | 人物の足元に、楕円形の薄い影を描く |
| 境目 | 3-3 で補正したマスクで、境目を少しぼかして混ぜる |

### 3-6. 性能・メモリ

パノラマの 3D 表示と切り抜きモデルが同時に載るため、調査資料の対策をあわせて入れる。

| 対策 | 内容 |
| --- | --- |
| A | アンチエイリアス（MSAA）を切る。iPhone では描画解像度の倍率を 1.5 に |
| B | パノラマのテクスチャのミップマップを作らない |
| E / J3 | 描画速度を見て、メッシュの細かさや描画解像度を下げる |
| J1 | テクスチャ圧縮（KTX2）。サーバー処理に移したあとで検討 |
| 解放 | モード終了時に、切り抜きモデル・カメラの映像トラック・テクスチャを確実に解放する |

### 3-7. フォールバック

| 状況 | 対応 |
| --- | --- |
| 切り抜きモデルが動かない・遅すぎる | 人物を入れずに、360度ビューとして表示する |
| 奥行きマップがない | パノラマを平面（球の内側）で表示し、人物は常に手前に重ねる |
| カメラの許可が得られない | 360度ビューとして表示する |

## 4. 未決・要確認事項

| 項目 | 内容 |
| --- | --- |
| モードの位置づけ | 360度ビュー／AR に加える 3 つ目の表示モードにするか、AR モードの中身をこれに置き換えるか |
| 前面・背面カメラ | 両方に対応するか、どちらかに絞るか |
| **奥行きマップのスケール** | 今の奥行き推定（Depth Anything V2 の相対版）は、メートル単位ではなく相対的な値。人物の距離（メートル）と比べる「手前の物による隠れ」には、メートル単位の奥行き（例：Metric Outdoor 版のモデル）か、スケールの合わせ込みが必要 |
| 複数人の扱い | 使うモデルが人物ごとに切り抜きを分けられるか。全員が 1 つのマスクになる場合は、つながっていない領域ごとに分けて距離を出す |
| カメラの画角 | A5 の推定を入れるまでは、機種ごとの仮の値をどう持つか |
| iPhone での速度 | Image Segmenter が、パノラマの描画と同時に 15 回/秒以上で動くか |
| プライバシー | 他人を写して合成できることへの注意表示。録画・共有機能を付ける場合の扱い |

## 5. 実装の順番

| 段階 | 内容 | 確認すること |
| --- | --- | --- |
| 1 | カメラ映像を WebGL に取り込み、パノラマと同じ画面に描く（C2） | 描画速度、メモリ |
| 2 | 人物の切り抜きを入れ、人物だけをパノラマの上に重ねる（距離なし、常に手前） | 切り抜きの速度、境目の見た目 |
| 3 | センサーの融合（D1）でパノラマを見回せるようにする | 揺れが減ったか |
| 4 | 足元方式・身長方式で距離を推定し、人物の大きさと位置に反映。足元の影を付ける | 距離が安定しているか、浮いて見えないか |
| 5 | 境目の補正（G4・G5）と色合わせ（H1） | 合成の自然さ |
| 6 | （必要なら）手前の物による隠れ、体のふくらみ | 4 章のスケールの問題を解決してから |

## 6. 評価の方法

- **安定性**：同じ端末で、今の AR と人物合成モードをそれぞれ数分動かし、落ちる・読み直されるまでの時間を比べる。
- **描画速度**：描画と切り抜きの 1 秒あたりの回数をデバッグパネルに出し、ログに残す。
- **距離の精度**：巻尺で 2m・3m・5m の位置に人を立たせ、推定距離との差を記録する（足元方式・身長方式それぞれ）。
- **体験**：利用者に今の AR と比べてもらい、「合成っぽさ」「その場にいる感じ」を 5 段階で評価してもらう。
